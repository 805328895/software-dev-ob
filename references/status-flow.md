# 需求流转链路

状态流转 = 改 frontmatter 的 `status` 字段，Dataview 看板/仪表盘自动同步。

```
需求创建 → 评审中 → 开发中 → 测试中 → 已完成
```

| 状态 | 含义 | 触发动作 |
|------|------|---------|
| 需求创建 | 刚提需求，填描述 | 调研代码确认可落地，生成需求文档 |
| 评审中 | 确认范围/方案 | 补涉及接口/表 |
| 开发中 | 写代码 | 按「改动点」逐项实现，勾 checkbox |
| 测试中 | 部署测试环境验证 | 写测试用例 + 报告，填验证结果 |
| 已完成 | 验证通过 | 填 deployed 部署日期 |

## 各 skill 与状态的对应

| skill | 触发时 status | 流转后 status |
|------|---------------|---------------|
| ob-new | （新建） | 需求创建 |
| ob-flow | 任意 → 目标 | 目标 |
| ob-impl | 评审中 | 开发中 → 测试中 |
| ob-tc | 开发中/测试中 | 不改 |
| ob-tr | 测试中 | 不改 |
| ob-flow（部署后） | 测试中 | 已完成（+deployed） |

## 约束

- 状态流转只改 `status` 字段，不手改看板文件
- `property:set` 后必须 `$CLI reload`，否则 `property:read` 读不到新值
- implemented 之前改动点 checkbox 必须全勾，否则不流转到测试中
