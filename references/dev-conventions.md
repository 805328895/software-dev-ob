# 仓库开发规范（纯指针）

> 本文件**不内置任何语言/框架规范**。各仓库的开发规范以其自身 `CLAUDE.md`（或等价文档）为准，implement skill 直接读仓库 `CLAUDE.md` 执行。

## 用法

`ob-impl` 实现需求时：

1. 读仓库根的 `CLAUDE.md`（或 `.mdc` 规则文件、CONTRIBUTING 等），按其中的开发约定写代码
2. 查询/更新/新增/校验/时间字段等规范一律遵循仓库 `CLAUDE.md`，skill 不重复定义
3. 若仓库没有 `CLAUDE.md`，按该仓库现有代码风格对齐（读同类已有实现模仿）

## 为什么不内置

不同语言/框架/项目规范差异大（Java MyBatis、Python Django、前端 React……）。内置某一套会绑死工具，反而不通用。规范权威源在仓库自身，skill 只负责"实现时遵守仓库规范"这个约束，不负责定义规范内容。

## implement 的护栏（与语言无关）

无论什么语言/框架，`ob-impl` 遵守这几条通用约束（不依赖具体规范）：
- 实现的接口/表/字段必须与需求文档「涉及接口/数据模型」对得上，不臆造
- 改动点 checkbox 逐项实现、逐项勾上，不整体跳过
- 与代码现状矛盾时停下来提问，不擅自改需求或绕过
- 优先复用仓库已有逻辑，不重复造轮子
